Game Rules

🇬🇧 English

Base58Check adds “1” characters for each leading zero byte, which is required behavior for legacy Bitcoin addresses. That is why a legacy address with version byte 0x00 can start with 1.

P2SH is now handled correctly: first a redeem script of the form 0014{HASH160(pubkey)} is built, then HASH160 is applied to this script, and only after that it is encoded using Base58Check with prefix 0x05.

Bech32 is created as witness version 0 plus a 20-byte pubkey hash converted from 8-bit bytes into 5-bit groups, so a valid native SegWit address starts with bc1q.

What reverse validation does

For 1... addresses, the code decodes Base58Check, verifies checksum, checks version byte 0x00, and compares embedded pubKeyHash with HASH160(pubkey), since this is how P2PKH is constructed.

For 3... addresses, the code rebuilds the redeem script 0014 + HASH160(pubkey), then computes HASH160(redeemScript) and compares it with the Base58Check payload, matching the P2SH-P2WPKH scheme.

For bc1... addresses, the code parses Bech32, validates checksum, HRP bc, witness version, and witness program length, then compares the program with HASH160(pubkey) for v0 P2WPKH.

Conclusion

If the final output shows ALL CHECKS PASSED: YES, it means the address is structurally valid, the private key matches the public key, and the address can be fully reconstructed from that key without inconsistencies.

Generator verification logic strictly follows Bitcoin address derivation rules and checksum validation standards.

🇺🇦 Українською

Base58Check додає символ “1” за кожен початковий нульовий байт, що є обов’язковою поведінкою для старих Bitcoin-адрес. Саме тому legacy-адреса з version byte 0x00 може починатися з 1.

P2SH тепер обробляється правильно: спочатку створюється redeem script формату 0014{HASH160(pubkey)}, потім застосовується HASH160, і лише після цього виконується кодування Base58Check з префіксом 0x05.

Bech32 створюється як witness version 0 плюс 20-байтовий pubkey hash, переведений із 8-бітних байтів у 5-бітні групи, тому коректна SegWit-адреса починається з bc1q.

Що робить зворотня перевірка

Для 1... адрес код декодує Base58Check, перевіряє checksum, version byte 0x00 і порівнює pubKeyHash з HASH160(pubkey), як це визначено в P2PKH.

Для 3... адрес код відтворює redeem script 0014 + HASH160(pubkey), обчислює HASH160(redeemScript) і порівнює з Base58Check payload згідно P2SH-P2WPKH.

Для bc1... адрес код розбирає Bech32, перевіряє checksum, HRP bc, witness version і program, після чого порівнює з HASH160(pubkey).

Висновок

Якщо вивід містить ALL CHECKS PASSED: YES, це означає, що адреса коректна, ключі відповідають один одному, і адреса повністю відновлюється з публічного ключа.

Generator повністю дотримується стандартів Bitcoin-адресації та криптографічної перевірки.

🇷🇺 По-русски

Base58Check добавляет символ “1” за каждый ведущий нулевой байт, что является обязательным поведением для старых Bitcoin-адресов. Поэтому legacy-адрес с version byte 0x00 может начинаться с 1.

P2SH теперь обрабатывается корректно: сначала собирается redeem script вида 0014{HASH160(pubkey)}, затем применяется HASH160, и только после этого выполняется Base58Check-кодирование с префиксом 0x05.

Bech32 формируется как witness version 0 плюс 20-байтовый pubkey hash, преобразованный из 8-битных байтов в 5-битные группы, поэтому корректный SegWit-адрес начинается с bc1q.

Что делает обратная проверка

Для адресов 1... код декодирует Base58Check, проверяет checksum, version byte 0x00 и сравнивает pubKeyHash с HASH160(pubkey), как в P2PKH.

Для адресов 3... код пересобирает redeem script 0014 + HASH160(pubkey), затем вычисляет HASH160(redeemScript) и сравнивает с Base58Check payload по схеме P2SH-P2WPKH.

Для bc1... адресов код парсит Bech32, проверяет checksum, HRP bc, witness version и program, затем сравнивает program с HASH160(pubkey).

Итог

Если вывод показывает ALL CHECKS PASSED: YES, это означает, что адрес валиден, ключи совпадают, и адрес полностью восстанавливается из публичного ключа без расхождений.
